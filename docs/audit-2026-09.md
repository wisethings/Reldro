# Production audit: September 2026

Scope: routes, authentication and permissions, every server action, API routes, lists and filters, date and status logic,
forms, error handling, performance hot spots, responsive behaviour. Method: read the code path for every action and route,
then exercise the running app (development and production builds) as a company admin, a supervisor, a worker and a user
from a second company.

Severity: P0 data loss or security, P1 major workflow bug, P2 meaningful UX or functional issue, P3 polish.

## Fixed in this pass

| # | Sev | Area | Problem | Root cause | Fix |
|---|-----|------|---------|------------|-----|
| 1 | P0 | Auth | A deleted person, or a removed company admin, kept full access for up to 14 days. | The session cookie is a stateless JWT carrying role, company and employee id; nothing re-checked it against the database. | `requireSession` now re-reads the account on every request (`getFreshSession`, cached per request). Deleted users are signed out immediately; role and company changes apply at once. Verified end to end. |
| 2 | P0 | Inspections | Deleting a checklist silently erased every completed inspection that used it (results, failed items, evidence). | `Inspection.template` is `onDelete: Cascade`; the confirmation only mentioned scheduled inspections. | `deleteTemplate` refuses when completed inspections exist and says why. No schema change. |
| 3 | P1 | All actions | In a production build, every message thrown from a server action (about 100 sites) shows the user "Minified React error #441" instead of the real reason, for example "3 corrective actions are not verified yet" when closing a report. Invisible in development and in the e2e suite. | Next.js masks the message of any error thrown out of a server action in production. | Expected failures are now returned with `fail()` and turned back into errors by `unwrap()` (automatic in `useAct`). Verified against a production build. |
| 4 | P1 | Dates | Two pages disagreed about what is overdue: items due today counted as overdue in some lists and "Due today" in others. About 15 different comparisons. | Each page compared `dueDate < now`; labels used a different calculation. | One definition in `src/lib/safety/dates.ts` (a due day is on time all day, overdue from the next day, counted in UTC). Used by Overview, Actions, Inspections, Sites, Insights, Reports, Qualifications, emails and AI summaries. Date formatters now pin UTC so date-only values never shift a day. |
| 5 | P1 | Inspections | Completing an inspection twice (double click, two people) created duplicate corrective actions and a duplicate "next" inspection. | Check-then-update with no atomic claim. | The completion is claimed with a conditional update; the second submit gets "already complete". |
| 6 | P1 | Inspections | A recurring inspection completed late scheduled its successor from the old due date, so it was overdue the moment it appeared. | Next due = previous due + interval. | Next due = later of (previous due, today) + interval. |
| 7 | P1 | Training | "Acknowledged, last 30 days" was wrong: it divided by every talk times every employee in the company, ignoring site-specific talks and, for supervisors, their scope. | Count-based formula on unscoped totals. | Computed per talk against the people it was addressed to, inside the viewer's scope. |
| 8 | P1 | People | Deleting a person left their reports, actions, inspections, investigations, incident roles, site lead and escalation rules pointing at nobody, and their qualifications behind as "Someone". | No cleanup; no foreign keys on those columns. | Delete now hands their work back to "no owner" and removes their qualifications, in one transaction. |
| 9 | P2 | Authorization | A supervisor with no home site could delete company-wide toolbox talks, publish to the whole company, and manage qualifications of other unassigned people. | `null === null` comparison on site id. | Site must be set. Acknowledging a site-specific talk now also requires being at that site. |
| 10 | P2 | Performance | Report, action and insight lists selected whole rows, including up to three inline photos per report (megabytes per page). | `include` instead of `select`. | List queries select only the columns they draw (`src/lib/safety/selects.ts`). Sites page no longer scans every scheduled inspection. |
| 11 | P2 | Performance/cost | The support chat polled the database every 30 seconds from every open tab, including background tabs. | Unconditional interval. | Skips while the tab is hidden. |
| 12 | P2 | Security | Secret checks on admin routes used `===` and accepted the secret in the URL. | Plain comparison. | Constant-time comparison (`secretMatches`). URL secrets still work for the manual tools; see "Remaining risks". |
| 13 | P2 | UX | Filters and tabs scrolled the page to the top and felt like a reload. | Links without `scroll={false}`; router `push` per keystroke. | `QueryLink` and `replace(..., { scroll: false })` everywhere. |
| 14 | P2 | UX | Nine destructive actions used the browser's `confirm()`; others used dialogs. | Grown piecemeal. | One `useConfirm` dialog used everywhere. |
| 15 | P2 | Errors | Some handlers had no error path (resend invite, remove admin, support message). | Missing `try/catch` around transitions. | Added, with plain-language messages. |
| 16 | P3 | Forms | Textareas opened as large empty boxes; inputs lacked contrast. | Fixed `rows`. | Shared `Textarea` auto-grows; stronger borders and focus rings; inline error support on `Field`. |

## Verified, no problem found

- Every server action checks its caller server-side and scopes by company. Direct URL access to admin pages as a worker or
  supervisor is refused; the CSV export returns 403.
- Cross-company: a second company's admin gets 404 on another company's report, action, investigation and qualification
  ids, and sees none of their data in lists.
- Incident times are sent with the browser's time zone; no offset bug.
- No console or hydration errors on about 30 pages across three roles; no sideways scrolling at phone width on the pages
  tested.

## Open items (not changed; documented)

**P2**
- Helpers that load a record and throw when it is missing or not visible (`loadAction`, `loadReportForActor`, `loadIncident`,
  `loadInvestigation`, `manageableQualifications`, `personForAdmin`) still throw, so a stale page shows a generic error
  in production. They only trigger on stale or forged ids. Convert to `fail()` when next touched.
- Passwords changed or accounts locked do not end other live sessions (sessions are stateless apart from the account
  check above). Add a `sessionsValidAfter` column to fix properly.
- Photos are stored as data URIs in Postgres (report, action evidence). Fine at current volume; move to object storage
  before volume grows.
- Schema changes run through a runtime SQL patch rather than migrations.
- The seed endpoint can wipe a database through a GET request when `ALLOW_DESTRUCTIVE_SEED=true`. Keep that variable unset.
- Buttons, cards and badges are still hand-styled in about 40 places; `FormParts`, `surface`, `QueryLink` and `useConfirm`
  exist now, adopt them as pages are touched.
- Report, action and investigation forms have not had the guided/progressive redesign yet.

**P3**
- Some lists load all employees to map names (People, Training, Sites); fine under a few hundred people.
- Site cards and some tables truncate long names with an ellipsis rather than wrapping.
